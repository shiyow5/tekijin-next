# ADR-0006: C6 スコアラーの R@3 天井は「証拠カバレッジ」であり、パラメータ調整では上がらない

- ステータス: 承認。2026-11-04 に #95 で資格・スキル・案件を C6 の証拠から外した（一般組織向けへの作り替え、ADR-0012）。この ADR の測定はそれらを含む証拠で出したもので、今のスコアラーには当てはまらない。実装は `company-v1` タグに残る
- 日付: 2026-08-25
- 決定者: A チーム（研究・実測に基づく）

## 背景

gold トピックを与えた層2 person Recall@3 が実埋め込みで **~0.80** で頭打ちし、spec §7 の目標 0.90 に届かない。「C6 の線形重み・飽和・base_score を調律すれば上がるのか？」を、実 Nemotron 埋め込み＋本番同型の候補集合で厳密に測った（`scripts/research_c6_sweep.py`・DGX throwaway pgvector）。

## 選択肢

- 案A: C6 のパラメータ（`Weights` の線形係数・`edge_weight` の飽和 `scale`・`BASE_SCORE_*`）を調律して R@3 を上げる。
- 案B: スコア関数の形（sum→max 等）を作り替える。
- 案C: パラメータでは上がらないと結論し、真のレバー（証拠カバレッジ＝データ）へ資源を振る。

## 決定

**案C**。実測で以下が確定した（62 person-gold 行・候補プールは全件 top_k=10）：

- **候補プール recall = 0.952**（gold 専門家はほぼプールに居る）→ retrieval/プールは天井でない。
- **R@3 はパラメータに完全非依存**：`Weights` の全振り・`edge_weight` の `scale`(1→8)・`BASE_SCORE_*` の
  極端なリバランス（案件 lead 0.8→1.5）でも **R@3(primary)=0.7957 / R@3(alt)=0.8182 が不変**。
  スコア値自体は変化する（例 q1 の候補 35: 0.65→0.62）が、**強候補の相対順位が変わらない**（順位は
  証拠のボリュームで決まり、リバランスは全候補を比例スケールするだけで再順序化しない）。
- **取りこぼしの内訳**：証拠ゼロ（=行動痕跡皆無・データ欠損）は **2件のみ**。残り **27件は gold が
  topic 証拠を持つのに、より証拠豊富な非 gold に正当に負ける**。alt(回答由来) R@3=0.818 > primary(案件由来)
  0.796 も、スコアラーが可視証拠でランクしている（案件に居ただけの薄い証拠より、答えた実績が効く）ことを示す。

したがって **R@3~0.80 は C6 の原理的天井**であり、パラメータのバグでも調律不足でもない。案件由来の
gold（薄い証拠）と「証拠が厚い人」ランキングの**グラウンドトゥルースの緊張**が本質。案B（max 型等）は
「1件の強い証拠が5件の中程度に勝つ」という不自然な設計で、overfitting リスクが高く採らない。

## 影響

- **C6 のパラメータ調律を推薦精度向上の手段として追わない**（#63/#85 系の重み探索は打ち止め）。既定値を維持。
- **真のレバーは「証拠カバレッジ（データ）」**：人ごとのトピック活動（answers / projects / daily_reports）を
  実態に近く厚くすると、薄い gold に可視証拠が付き R@3 が上がりうる。→ **#326（営業日報を CRS 訪問
  フォーマットで実態化）** がこの領域に直結。合成 fixture の証拠カバレッジ拡充が次の主レバー。
- spec §7 の目標 0.90 は「スコアラーを詰める」ことでは到達せず、**データ側（証拠密度）と gold 定義**の
  問題として扱う。層別・alt gold での監視は継続（[[tekijin-eval-basis]]）。
- 恒久ハーネス `scripts/research_c6_sweep.py`（候補プール recall 診断＋重み/scale/base_score スイープ＋
  取りこぼしの証拠有無内訳）を残す。コーパス/埋め込みが変わったら再実行して天井を測り直す。
- 関連: #222（`edge_weight` 飽和で確信度ラベルが張り付く）も同根＝飽和は確信度表示の問題であって
  ランキングの律速ではないことが本 ADR で確認された。

## 追補（2026-08-25）: データ側レバーも実測で天井を動かさない（#326 / #355）

「真のレバーは証拠カバレッジ（データ）」を実際に引いて測った結果、**データ側でも R@3 は動かなかった**。
これは本 ADR の「証拠カバレッジ天井」を、さらに「**gold のグラウンドトゥルースの緊張**」まで掘り下げる。

- **#326（日報を CRS フォーマットで実態化・トピック語を厚く）**: DGX ペア測定で
  primary R@3 **0.7957→0.7903（−0.0054）**・alt 0.8182 不変。日報を厚くして gold（projects+daily
  由来）が営業reps を上位化しても、当時のスコアラーは日報を証拠源にしていなかったため R@3 は微減した。
- **#355（日報をスコアラーの証拠源に追加してその非対称を解消）**: `collect_topic_evidence` に日報を
  加え（`DailyReport.topics` を seed 時付与＝gold と同一 match_topics、`BASE_SCORE_DAILY=0.15`、
  `DAILY_EVIDENCE_CAP=5`）、DGX で daily ON/OFF を測定 → **ON=OFF=0.7903 で完全一致・順位変化ゼロ**。
  日報証拠は実際に効いている（probe: 営業rep 72–79 件の on-topic 日報、個々のスコアは +0.002〜+0.03 動く）
  が、**強候補は案件/回答で `topic_fit` が既に飽和**しており、上限 0.75 の日報では順位が動かない。かつ
  日報は gold・非 gold の双方へ対称に加わるため再順序化しない（本 ADR の「順位＝証拠ボリューム、
  比例スケールは再順序化しない」の直接の帰結）。

**結論の更新**: R@3~0.80 の天井は「スコアラーが見ていない証拠源の欠落」ではない。**薄い gold（活動痕跡が
全信号で希薄）と証拠豊富な非 gold の、グラウンドトゥルースの緊張**である。モデル側（C6 重み/飽和/base_score・
C1 トピック媒介 #69・BM25 #114・prior_answer #327）に続き、**データ側（#326 の証拠拡充・#355 の新しい証拠源
追加）も出し尽くして R@3 は動かない**。真に動かすには (a) gold 定義そのものの見直し、または (b) 質的に新しい
識別信号——**知識の構造化（#357 知識フレームワーク：生データを知識単位へ変換し関係で持つ）**が要る。
`#63/#85` に加え、**「同種の証拠を増やす／新たな証拠源を足す」路線も打ち止め**とする。

なお **#355 自体は R@3 とは独立の product 価値**を持つ（既定 OFF で温存）: 案件も回答もまだ持たない
新人営業のように「日報だけが痕跡の人」を surface できる＝**暗黙知の early capture**。現行 eval は
専門家＝案件リードなので効果が出ないだけで、日報のみ専門家がいるコーパスでは有効化を再検討する。

## 追補2（2026-08-25）: リランキングの2大レバーも実測で天井を破れない＝律速はデータ/gold

ユーザーが R@3 0.90 到達を必須要件とし、「バグの可能性」「賢いアーキ」を求めたため、独立の
バグ監査（general-purpose agent・fixtures から再現）と、未検証だった2つのリランキング手法を DGX 実測した。

**バグ監査の結論: バグ無し。** 埋め込み prefix・候補プール・証拠収集・R@3 計算・経路信号すべて実装は正しい。
天井の**機序**を特定: `edge_weight = saturate(sum(base_score))` は証拠2〜3個で topic_fit≈0.95-0.99 に飽和し、
主役 0.45*topic_fit が強候補全員でほぼ定数化＝順位を決めていない。**総和の単調変換では薄い証拠 gold を
厚い証拠 non-gold の上に出せない**（数学的事実）。監査が名指しした唯一未検証のレバー＝「総和でなく
識別的（希少度/特異性）な topic_fit」。

**実験①: 識別的 topic_fit（証拠タイプの IDF 重み・飽和有無）** — `scripts/research_c6_discriminative.py`。
topic_fit 単体順位で R@3 測定（62 person-gold・pool recall 0.952）:
- baseline saturate(sum) = raw sum(no sat) = **0.7742**（primary）＝**飽和は順位の犯人でないと確認**（両者完全一致）。
- idf-weighted = **0.7796**（primary +0.005 / alt −0.006）＝**ほぼ中立・天井を破れない**。証拠タイプの希少度では識別力不足。

**実験②: LLM リランカー（本命）** — `scripts/research_c6_llm_rerank.py`。候補プール(recall 0.952)の
プロフィール/案件商材/過去回答を本番 vLLM(Qwen3.6-35B) が読んで並べ替え、R@3 を決定的 baseline と比較:
- baseline(決定的) primary **0.7903** / alt **0.8182**。
- **LLM rerank primary 0.7151（−0.075）/ alt 0.6424（−0.176）＝大幅悪化**（LLM 出力失敗 0/62・全件有効に並べた上で悪化）。
- 特に alt(回答由来 gold)の落ち込みが大＝**LLM はプロフィールの尤もらしさで判断し、「実際にそのトピックで
  答えた実績」を決定的スコアラーほど重視しない**。証拠カウントが実は強い。

**結論（追補2）: リランキング（決定的な識別化・LLM の意味理解）のどちらでも 0.80 を超えられない。**
候補プールには正解が居る（0.952）のに上位3に入らないのは、**gold の ~20% が薄い証拠しか持たず、
あらゆる順位付け信号で厚い証拠の非 gold に正当に負ける**ため。これは順位関数の問題でなく **データ/gold の問題**。
0.90 への残る道は (a) **gold/語彙の取りこぼし修正**（E2E 実数は 62件で 0.79 だが全66件では ~0.75。人手ラベルの
トピックが22語彙に無く gold_topics 空→強制 R@3=0 の4件。語彙拡張で回収可）、(b) **薄い証拠 gold に痕跡を与える
データ拡充**（チャット履歴等を証拠源化＝#355 の一般化）、(c) **gold ラベル自体の再検証**（痕跡皆無の専門家は
どの手法でも救えない＝合成コーパス/gold 定義の限界の可能性）。**「同種の証拠を増やす」でも「賢い順位付け」でも
0.90 は出ない**——構造化知識(#357)・データ拡充・gold 再定義が本筋。
