# ADR-0012: 対象を任意の組織に広げ、Discordの発言も詳しさの根拠に使う

- ステータス: 承認
- 日付: 2026-10-27
- 決定者: shiyow5(個人開発の所有者)
- 関連: Issue #64 / `docs/plans/2026-10-27-general-org-redesign.md`

## 背景

TEKIJINはインターン先の1社向けに作り、社員名簿・日報・22語のトピック語彙・87行の合成評価セットを前提にしていた。インターンが終わって個人のプロダクトになり、会社という背景が無くなった。

新しい対象は、DiscordやSlackを中心に会話している任意の組織である。名簿や日報は無く、知識源は会話と、Google ドキュメント/スライドやNotionページになる。答えられない質問を詳しい人へ繋ぐには、誰が何に詳しいかを、これらの情報源から推定する必要がある。

Discordの開発者ポリシー(施行 2024-07-08)の第16条は、APIで得たデータを使ってDiscordのユーザーをプロファイリングすることを禁じている。会話の発言から人の詳しさを推定する処理は、これに当たるおそれがある。

## 選択肢

- 案A: 発言を詳しさの根拠に使うのは、本人が参加登録して同意した人に限る。登録していない人は、自己紹介スライドや文書の作者など、Discord以外のデータだけで推薦する。
- 案B: 登録していない人も含め、全員の発言を詳しさの根拠に使う。手当てとして、組織ごとの設定、本人の除外の申し出、組織外への非公開を入れる。

## 決定

案Bを採用する。所有者が、第16条に触れてボットが停止される危険を承知したうえで選んだ。試す組織は所有者自身の組織で、告知も所有者が行う。会話からの推定を最初から使えないと、立ち上げ期の推薦の根拠がほとんど無くなる。

手当ては次のとおり。

- 発言からの推定は組織ごとの設定 `expertise_from_messages` で切り替え、既定はオフにする。所有者の組織ではオンにする。
- `/tekijin optout` を打った人は推薦の対象から外し、その人を根拠にした推定データを消す。
- 推定した詳しさは組織の外に出さない。推薦の理由は質問した本人にしか見せない。
- メッセージ本文をモデルの学習には使わない(第21条)。推論と検索にだけ使う。

## 影響

所有者の組織では、会話の実績から詳しい人を推薦できる。そのかわり、ボットがDiscordの規約違反と判断されて停止される危険が残る。ほかの組織に提供するときは、既定のオフのまま案Aと同じ動きになるので、この危険は所有者の組織に限られる。

対象の変更にともない、日報・資格・案件・支店・22語の語彙・合成の会社データとその評価セットは消す。会社向けの最後の状態は `company-v1` タグで残す。過去のADRのうち、0004・0006・0007は87行の合成データで出した結論なので、新しい前提では根拠にならない。

## その後の判断

2026-11-04、R3で、取り込んだ会話を回答に使うにあたり、そのチャンネルを読めない人には会話を見せないことにした(#85)。Discordの `/ask` では質問者の権限で絞り、Webでは @everyone が読めるチャンネルの会話だけを見せる。権限が分からない会話は誰にも見せない。

2026-11-05、R4で、GoogleとNotionの取り込みのコードを入れた(#100、#102)。ただし、鍵がサーバーの環境変数に1組だけある形では、運用者個人の鍵で文書を読むことになり、組織を増やせない。ユーザーの判断で、鍵を組織ごとに登録できるようにするまで(#103)、取り込みは有効にしない。

トピックの語彙は、振り返りの入力検査とSlackからの知識の抽出がまだ使うので、R3では消さずに残した。知識の形を作り直すR6で置き換える。

2026-11-05、R5で、メンバーの自己紹介を推薦の根拠として取り込むことにした(#106)。自己紹介チャンネルへの投稿は、`expertise_from_messages` がオフでも使う。この設定で扱いを分けているのは、普段の会話から詳しさを推し量ることで、本人はその発言が根拠になるとは思っていない。自己紹介チャンネルへの投稿は、本人が自分の得意なことを組織に知らせるために書いたもので、スライドや `/tekijin join` で書いた申告と同じ扱いにできる。TEKIJINは書かれた文をそのまま根拠として持ち、ほかの発言から推し量ることはしない。`/tekijin optout` を打った人の分は消し、見せる範囲はチャンネルの権限に従う点は、ほかの発言と同じにした。

2026-11-05、R5で、組織のメンバーの質問に詳しい人を推薦できるようにした(#107)。質問に近い自己紹介、文書、会話、TEKIJIN経由の回答を集め、その書き手に順位から点数を付けて足す。会話を根拠にするのは `expertise_from_messages` がオンの組織だけにした。根拠ごとに質問とのコサイン類似度の下限を置き、無関係な質問で誰かを推薦しないようにした。下限は架空のサークルで測って決めた値で、実際の組織で測り直す(R7)。経路の判定(C5)に渡す人の確信度には、自己紹介と回答の類似度だけを使う。文書と会話の類似度は、すでに文書の確信度として経路の判定に入っているからだ。両方を入れると、サークルの質問28問のうち12問が、文書から答える経路から人へ繋ぐ経路に変わった。
