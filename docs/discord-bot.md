# Discordボットの立ち上げ

Discordで `/ask 質問文` と打つと、TEKIJINが答えを返す(Issue #60)。`/tekijin join` などでTEKIJINへの参加や設定ができる(Issue #66)。返事は質問した本人にだけ見える。質問には顧客名や社内のトラブルが入りうるうえ、打ったチャンネルを誰が見ているか分からないからだ。

| TEKIJINの判断 | Discordへの返事 |
|---|---|
| 知識・文書・過去の回答で答えた | 回答と出典 |
| 人に相談するのがよい | 推薦された人と、1人につき3つまでの理由(1行に1つ)。組織のメンバーの質問では、理由に根拠の出典が付く(「自己紹介: …」「『機材の使い方と管理マニュアル』を書いた」など、Issue #107)。出力先のチャンネルを設定していれば「依頼する」ボタンが付く(下の「依頼のスレッド」)。設定していなければWebのURLを出し、依頼を送るにはWebで同じ質問をし直す |
| 質問が足りない | 聞き返しの文と、`/ask` のし直しかWebで続ける案内 |
| 答えられない | その旨 |

依頼のスレッドと知識の確認はIssue #114で足した(下の節)。

## 仕組み

ボットはバックエンドとは別のプロセスで動く(`python -m tekijin.discord_bot`)。スラッシュコマンドはGateway経由で届くので、ボットのために公開URLを用意する必要は無い。メッセージ本文を読まないので、特権intent(MESSAGE_CONTENT)も要らない。

ボットは受けた質問を、バックエンドの内部API `POST /internal/discord/ask` に送る。認証は共有シークレット(ヘッダ `X-Tekijin-Bot-Secret`)で行う。バックエンドはDiscordのユーザーをTEKIJINのメンバーに対応づけ、Webの質問と同じグラフを最後まで流し、結果を1つにまとめて返す。聞き返しの続きはDiscordから行えないので、返事を作ったあとにその実行を打ち切る。取次ぎも、出力先のチャンネルが未設定なら同じく打ち切り、推薦された人の受信箱には、まだ送っていない依頼は載らない。設定していれば、「依頼する」で送れるように実行を残す。

TEKIJINは、`TEKIJIN_DISCORD_GUILD_ID` で指定した1つのサーバーを1つの組織として受け持つ。ほかのサーバーからの呼び出しには「このサーバーでは使えません」と返す。サーバーのメンバーは、初めて `/ask` などを打った時点で自動でTEKIJINのメンバーになる。対応表を書く必要は無い。

| コマンド | 内容 |
|---|---|
| `/tekijin join` | 参加を登録し、Webにログインするための一回限りのURL(10分)を本人だけに返す。任意の `intro` 欄に自己紹介(1000字まで)を書ける |
| `/tekijin intro` | 自己紹介を登録する。前に登録したものと置き換わる。参加した人だけが使える(Issue #106) |
| `/tekijin optout` | 詳しい人として推薦される対象から外れる。登録してある自己紹介もすべて消える |
| `/tekijin optin` | 推薦される対象に戻る。消えた自己紹介は戻らない |
| `/tekijin add` | 文章かファイルをTEKIJINの知識に追加する。参加した人だけが使える。ファイルはテキスト(.txt)とMarkdown(.md)で200KBまで、本文と合わせて2万字まで。題名が無ければファイル名を題名にする。置き場所のURLは任意で、同じURLを送り直すと更新になる。更新できるのは追加した本人だけ(Issue #70、#74) |

## 手順

1. [Discord Developer Portal](https://discord.com/developers/applications) でアプリケーションを作り、Botタブでトークンを発行する。同じBotタブの下のほうにある「Privileged Gateway Intents」で「Message Content Intent」をオンにして保存する。会話の取り込み(下の節)で発言の本文を読むのに要る。トークンの再発行は要らない。
2. OAuth2 の URL Generator で、スコープに `bot` と `applications.commands` を選ぶ。権限は「チャンネルを見る(View Channels)」と「メッセージ履歴を読む(Read Message History)」を選ぶ。生成されたURLを開き、ボットをサーバーに招待する。
3. 共有シークレットを作る。例: `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`
4. バックエンドの `.env` に次を書き、バックエンドを再起動する。

   ```dotenv
   TEKIJIN_DISCORD_BOT_SECRET=<3で作った値>
   TEKIJIN_DISCORD_WEB_URL=http://localhost:3000
   TEKIJIN_DISCORD_GUILD_ID=<サーバーID>
   ```

   サーバーIDは、Discordの設定で開発者モードを有効にし、サーバー名を右クリックして「サーバーIDをコピー」で取れる。既存のDBには、先に `cd backend && PYTHONPATH=src python -m tekijin.data.migrate` で新しい列とテーブルを足す(データは消えない)。

5. ボットのプロセスに、4と同じ値に加えて次を渡して起動する。

   ```dotenv
   TEKIJIN_DISCORD_BOT_TOKEN=<1で発行したトークン>
   TEKIJIN_DISCORD_BACKEND_URL=http://127.0.0.1:8000
   ```

   ```bash
   cd backend && PYTHONPATH=src python -m tekijin.discord_bot
   ```

   `TEKIJIN_DISCORD_GUILD_ID` を入れると、コマンドはそのサーバーにすぐ出る。

`.env` は `chmod 600` にしておく。トークンとシークレットはコミットしない。

## 会話の取り込み

ボットは、サーバーで交わされた会話をTEKIJINに取り込む(Issue #76)。起動すると、チャンネルごとに取り込み済みの続きから過去の履歴を読み、そのあとは新しい投稿・編集・削除を10秒ごとにまとめてバックエンドへ送る。初めて起動したときは、ボットが読めるチャンネルとスレッドの履歴をすべて読む。止まっていたあいだの投稿も、次に起動したときに読み込まれる。

発言は、スレッドならスレッド全体、通常のチャンネルなら日本時間の1日分を1つの会話にまとめ、資料の一覧に「#チャンネル名 日付」の題名で並ぶ。Discordで消された発言は、TEKIJINからも消える。チャンネルやスレッドを丸ごと消した場合も、そこで交わされた会話を消す。ボットの発言、DM、本文の無い発言(添付だけなど)、ピン留めなどのお知らせは取り込まない。

取り込まないチャンネルは、ボットのプロセスに渡す設定で、IDをカンマ区切りで指定する。そのチャンネルの中のスレッドも取り込まない。

```dotenv
TEKIJIN_DISCORD_EXCLUDED_CHANNEL_IDS=123456789012345678,234567890123456789
```

除外を足しても、すでに取り込んだ発言は消えない。取り込みを始める前に、サーバーのメンバーへ告知しておく(設計書 docs/plans/2026-10-27-general-org-redesign.md の6章)。

## 自己紹介

TEKIJINは、メンバーの自己紹介を、誰が何に詳しいかの根拠として持つ(Issue #106)。自己紹介は次の3か所から集める。

1. 自己紹介の資料。題名に「自己紹介」を含む資料を `/tekijin add`・Web・GoogleやNotionの取り込みで登録すると、TEKIJINがその資料を区切り、各区切りをそこに名前のある人の自己紹介にする。区切りは「スライド1」のような行か見出しで決め、どちらも無ければ空行で決める。名前は空白を除いた表示名で照合する。名前が見つからない区切りと、2人以上の名前がある区切りは使わない。資料を更新すると作り直し、資料を消すとその分も消える
2. `/tekijin join` の `intro` 欄と `/tekijin intro`。1人1つで、書き直すと置き換わる
3. 自己紹介チャンネルへの投稿。名前が「自己紹介」を含むチャンネル(「自己紹介-2026」など)か `introductions` のチャンネルに書いた投稿を、書いた人の自己紹介にする。スレッドの中の返信は使わない。フォーラムの投稿の最初の発言は使う。投稿を編集すると自己紹介も変わり、消すと消える。チャンネルの記録を残すので、見せる範囲は会話と同じになる

自己紹介チャンネルへの投稿は、本人が組織に向けて書いた申告なので、組織の設定 `expertise_from_messages` がオフでも使う(ADR-0012)。

`/tekijin optout` を打つと、その人の自己紹介は3か所の分ともすべて消える。外れているあいだは、新しく書いても登録されない。`/tekijin optin` で戻っても、消えた分は戻らない。`intro` は書き直す。資料にあった分は、その資料が次に登録されたときに作り直される。

既存のDBには、先に `python -m tekijin.data.migrate` で自己紹介の表を足す。すでに取り込んである資料と投稿は、次に登録し直したときか、ボットが履歴を読み直したときに自己紹介になる。

## 見せる範囲

取り込んだ会話は、そのチャンネルを読める人にだけ見せる(Issue #85)。Discordで `/ask` すると、ボットが質問者の権限を調べ、閲覧と履歴の読み取りができるチャンネルの会話だけを回答の根拠にする。非公開スレッドは、そのチャンネルでスレッドの管理権限を持つ人にだけ見せる。個別に招待された人までは調べないので、その人たちには見せない。

Webには質問者のDiscordの権限が届かない。Webでの質問と「資料」の一覧では、@everyone が読めるチャンネルの会話だけを見せる。管理者は全部を見られる。

チャンネルの公開・非公開とスレッドの種類は、ボットが起動したときと、チャンネル・スレッド・@everyone の権限が変わったときにバックエンドへ送る。この情報が届いていない会話は、誰にも見せない。

#85より前に取り込んだ会話には、元のチャンネルの記録が無いので、そのままでは見せない。次のコマンドで、保存してある発言から書き込む。

```bash
cd backend && PYTHONPATH=src python -m tekijin.data.migrate
PYTHONPATH=src python -m tekijin.data.visibility backfill
```

## 依頼のスレッド

Discordから依頼を送り、回答を受け、知識の下書きを確認できる(Issue #114)。ボットが書き込めるのは、`TEKIJIN_DISCORD_OUTPUT_CHANNEL_ID` で指定した1つのチャンネルと、その下のスレッドだけにした。書き込みはすべて `discord_bot/output.py` を通り、ほかの場所には投稿しない。未設定なら新しい投稿は何もせず、`/ask` の返事も今までどおり本人にだけ見える形で、Webへの案内を出す。DMは使わない。

1. `/ask` の結果が人への相談なら、返事に「依頼する」ボタンが付く。押せるのは質問した本人だけ。押すと、Webで「チャットで相談」を選んだときと同じ処理で依頼が作られる
2. ボットが出力先のチャンネルに公開スレッドを作り、質問と依頼の文、承諾・辞退・「自分より適任がいる」のボタンを置く。チャンネルを見られる人には質問の内容も見える。ボタンを押せるのは依頼された本人だけで、処理はWebの `/answer` と `/handoff/refer` と同じサービスの関数に流れる。辞退すると次の候補に新しいスレッドで依頼が回る。「自分より適任がいる」では人を選ぶ欄が出て、選べるのはTEKIJINを使ったことがある人だけ
3. 依頼された人の名前は文字で書くだけで、通知は飛ばない。`TEKIJIN_DISCORD_MENTION_RESPONDERS=true` にしたときだけ、依頼された本人にメンションを付ける。それ以外の人(@everyone やロールを含む)には、どの投稿でも通知を飛ばさない
4. 承諾したあと、スレッドに書いた内容はWebのチャットにも載る。Webのチャットで書いた内容もスレッドに載る。依頼された人が書いた内容は回答(`answers`)として記録され、質問を出典にした事例(case)の下書きになる。承諾より前に書いた発言は回答にしない。Discordで発言を編集すると、記録した回答と確認前の下書きも直る。発言を消すと、その回答も消え、確認前の下書きから外れる。ボットが止まっていた間の発言は、次に接続したときに読み直す。下書きは管理者が確認するまで回答に使われない
5. `/tekijin review` で、確認を待っている下書きを本人にだけ見える形で4件ずつ出す。確認済みにするボタンと差し戻すボタン、続きを出す「次へ」が付く。使えるのは `TEKIJIN_DISCORD_ADMIN_USER_IDS` に書いたDiscordユーザーだけ

出力先のチャンネルの会話は、取り込みの対象から外す(回答は上の4で記録されるため)。Webで出した質問はDiscordには投稿しない。

ボタンは押した人とその時点の状態をバックエンドで確かめてから処理する。ボタンのIDには対象の番号が入っているが、それだけでは何もできない。ボットを再起動しても、前に出したボタンはそのまま使える。

APIのプロセスはDiscordと直接は話さない。スレッドに出すものはバックエンドの `discord_outbox` に積まれ、ボットが数秒ごとに読み出して投稿する。ボットのトークンはボットのプロセスだけが持つ。

設定はバックエンドとボットの両方の `.env` に書く。

```dotenv
TEKIJIN_DISCORD_OUTPUT_CHANNEL_ID=<依頼のスレッドを作るチャンネルのID>
# 既定は false。true のときだけ依頼された本人にメンションする
TEKIJIN_DISCORD_MENTION_RESPONDERS=false
# /tekijin review を使えるDiscordユーザーのID(カンマ区切り)
TEKIJIN_DISCORD_ADMIN_USER_IDS=<自分のユーザーID>
```

既存のDBには `discord_requests` と `discord_outbox` の2つのテーブルが要る。`cd backend && PYTHONPATH=src python -m tekijin.data.migrate` で足す(データは消えない)。

ボットには、出力先のチャンネルで次の権限が要る。チャンネルを見る(View Channel)、メッセージを送信(Send Messages)、公開スレッドを作成(Create Public Threads)、スレッドでメッセージを送信(Send Messages in Threads)、メッセージ履歴を読む(Read Message History)。intentは今までどおり、既定のものと Message Content Intent で足りる。

## 止め方

`TEKIJIN_DISCORD_BOT_SECRET` を空にしてバックエンドを再起動すると、内部APIは404を返し、Discordからの質問はすべて止まる。既定は空なので、設定しない限りバックエンドの動作は変わらない。
