# Notionのページの取り込み

Notionのページを、TEKIJINの資料として定期的に取り込む(Issue #101)。取り込んだページは資料の一覧に「Notion」として出て、質問への回答の出典になる。

TEKIJINは、Notionの内部インテグレーションとしてページを読む。内部インテグレーションは、1つのワークスペースの中だけで使う、プログラム用の接続である。メンバーがページにこのインテグレーションを接続すると、TEKIJINはそのページを読めるようになる。

## 仕組み

取り込みは、Googleの取り込みと同じプロセスで動く(`python -m tekijin.ingest.poll`)。このプロセスは既定では15分ごとに、インテグレーションが読めるページを Notion API の検索(`POST /v1/search`)で一覧する。データベースの行もページなので、1行ずつ取り込む。ゴミ箱に入ったページは取り込まない。

前回から最終更新日時も題名も変わっていないページは読まない。新しいページと変わったページは、中のブロックを順にたどって平文にし、保存する。読むブロックは、段落、見出し、箇条書き、番号付きリスト、ToDo、トグル、引用、コールアウト、コード、表の行である。画像、ファイル、埋め込み、区切り線などは読まない。題名はページのタイトル、出典のURLはNotionでそのページを開くURLになる。

子ページは、それ自体が検索の一覧に出るので、親とは別の資料として取り込む。親の本文には含めない。一覧に出ていない子ページだけを、親の本文の中に読み込む。入れ子は8段までたどり、それより深いブロックは読まない。本文が100万字を超えるページは、ログに記録して飛ばす。

Notion APIの上限は、1秒あたり平均3回である。TEKIJINはリクエストの間を0.34秒以上空ける。それでも上限を超えたという応答(429)が来たら、Notionが示す秒数だけ待ってから再試行する。混み合っているという応答(5xx)にも、間を空けて数回まで再試行する。

一覧に無くなったページ(接続を外した、削除した)は、TEKIJINからも消す。検索の途中で失敗した回は、何も消さない。1ページの読み込みに失敗しても、残りのページの取り込みは続け、失敗したページは次の回にもう一度読む。

取り込んだページは、組織のメンバー全員が見られる。インテグレーションに接続するのは、メンバー全員に見せてよいページだけにする。

## 準備(初回だけ)

### 1. 内部インテグレーションを作る

作れるのはワークスペースのオーナーだけである。

1. Notionにログインし、[インテグレーションの管理画面](https://www.notion.so/profile/integrations)を開く
2. 「新しいインテグレーション」を選ぶ
3. 名前(例: `TEKIJIN`)を付け、取り込むワークスペースを選び、種類は「内部」にする
4. 作ったインテグレーションの「機能」で、「コンテンツを読み取る」だけを有効にする。コンテンツの更新や挿入、コメント、ユーザー情報の権限は要らない

### 2. トークンをサーバーの `.env` に書く

インテグレーションの「構成」(または「シークレット」)の欄に、`ntn_` で始まるトークンがある。このトークンを持つ人は、接続したページをすべて読める。チャットやメールに貼らない。リポジトリに入れない。`.env.example` にも書かない。

トークンをコピーし、TEKIJINを動かすサーバーで、リポジトリ直下の `.env` に書く。`.env` は、TEKIJINを動かすユーザーだけが読めるようにする。

```bash
chmod 600 .env
```

```dotenv
TEKIJIN_NOTION_TOKEN=<コピーしたトークン>
TEKIJIN_DISCORD_GUILD_ID=<サーバーID>
# 取り込みの間隔(秒)。省略すると900秒(15分)
TEKIJIN_POLL_INTERVAL_S=900
```

取り込み先の組織は `TEKIJIN_DISCORD_GUILD_ID` で決まるので、Discordボットと同じ値が入っていることを確かめる。`TEKIJIN_NOTION_TOKEN` が空なら、Notionからは取り込まない。Googleの取り込みも設定していれば、同じプロセスが両方を取り込む。

トークンが漏れたときは、インテグレーションの画面でトークンを作り直し、`.env` を書き換えてプロセスを起動し直す。

## ページを接続する

取り込みたいページを開き、右上の「•••」から「接続」を選び、1で作ったインテグレーションを追加する。ページの子ページにも、同じ接続が引き継がれる。最上位のページに接続すれば、その下はすべて対象になる。あとから足した子ページも、次の回に取り込まれる。

インテグレーションの管理画面の「アクセス」タブからも、読めるページを選べる。

TEKIJINから消したいページは、そのページの「接続」からインテグレーションを外す。資料の画面で消しても、接続が残っていれば次の回にまた取り込まれる。

## 起動と停止

まず1回だけ取り込んで、動くことを確かめる。

```bash
cd backend && PYTHONPATH=src python -m tekijin.ingest.poll --once
```

ログの最後に、ページごとの件数(`listed`、`added`、`updated`、`deleted` など)が `provider='notion'` の行に出る。全部うまくいけば終了コードは0、一覧の取得やページの取り込みに1件でも失敗すると1になる。設定が足りないときは2で終了し、足りない設定の名前を表示する。

定期的に取り込むときは、`--once` を付けずに起動する。止め方と常駐のさせ方は、[Googleの取り込み](google-ingest.md#起動と停止)と同じである。

最初の回は、接続したページをすべて読むので、ページが多いと時間がかかる。TEKIJINは、ブロック100個ごとと、子を持つブロック1つごとにリクエストを1回送り、その間を0.34秒以上空ける。2回目からは、変わったページだけを読む。

## うまくいかないとき

| 症状 | 確かめること |
|---|---|
| `listing failed (HTTP 401)` が出る | トークンを正しくコピーしたか。作り直していないか |
| `listed=0` のまま増えない | ページの「接続」にインテグレーションを追加したか |
| ページの一部しか入らない | 読まない種類のブロック(画像、埋め込みなど)か、8段より深い入れ子ではないか |
| `skipped ... characters` が出る | そのページは100万字を超えている。ページを分ける |
| `could not fetch ... (HTTP 404)` が出る | 一覧のあとで接続が外れた。次の回に一覧から消える |

ログには、トークンを出さない。
